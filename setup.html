Your tracker, on every device.

GitHub Pages hosts the app. Supabase stores your jobs, notes, checklist and supplied research. Sign in with the same Supabase email/password on your phone and computer.

Current status: The app is built, but has not been connected to your Supabase project or published to your GitHub account. Follow the steps below to make cloud saving live. No build tools or command line are required.

1. Know which files go where

FilePurposeUpload to GitHub?
job-tracker-github-pages.zipExtract this: it contains the public appYes, its extracted contents
supabase-setup.sqlCreates your database and access rulesNot needed; run in Supabase
initial-tracker.jsonYour 28 opportunities, 27 prep tasks and private reference contextNo. Import inside the signed-in app.
setup.htmlThis guideIncluded in the app package

The public app contains no starter job research, phone number or email address. Keep initial-tracker.json and exported backups out of a public repository. The app asks you to sign in before loading your database.

2. Create your Supabase project

  1. Open Supabase Dashboard and sign in or create an account.
  2. Choose New project, select your organization, and name it something like job-tracker.
  3. Create a strong database password and save it in your password manager. This is a database administrator password; it does not go into the app.
  4. Select a nearby region and create the project. Wait until provisioning finishes.

3. Create the database table

  1. In the project sidebar, open SQL Editor and create a new query.
  2. Open the separate supabase-setup.sql file in a text editor. Copy its complete contents into the query.
  3. Click Run. You should see success with no returned rows.
  4. In Table Editor, confirm that tracker_state exists. It is empty until you import your tracker.

The SQL enables Row Level Security (RLS). Only an authenticated user can read and update a row whose owner ID matches their own user ID. Anonymous visitors have no table access. Do not disable RLS to resolve a configuration problem. Supabase RLS documentation.

4. Create your one sign-in account

  1. Open Authentication → Users.
  2. Use Add user → Create new user (the exact button label may vary). Enter the email you want to sign in with and a strong password.
  3. Select the option to auto-confirm the email, if offered, and create the user. This is your app sign-in password, separate from your database password.
  4. In Authentication configuration, keep the Email provider enabled. Turn Allow new users to sign up off. Leave anonymous sign-ins off. Supabase may place these settings under Sign In / Providers.
  5. Do not add other users. No sign-up button is present in this app.

Creating the user directly avoids email delivery and redirect setup for initial registration. The app uses email/password sign-in. If you forget the password, manage/reset the user through your Supabase dashboard. Authentication settings · Password-based authentication.

5. Connect the app to the project

  1. Extract job-tracker-github-pages.zip into a folder.
  2. Find your Project URL in the project's Connect dialog or project API settings. It looks like https://abcdefgh.supabase.co.
  3. Open Settings → API Keys and copy the publishable key (starts with sb_publishable_). A legacy anon key also works.
  4. Open config.js in a plain-text editor. Paste those two values between the quotes, keeping the commas and brackets:
window.TRACKER_CONFIG = {
  supabaseUrl: 'https://YOUR-PROJECT.supabase.co',
  supabasePublishableKey: 'sb_publishable_YOUR-PUBLIC-KEY'
};

Never use a secret key, service_role key, database password or your login password in config.js. A publishable key is intended for public client code; the sign-in token and RLS control access to your records. Supabase key types.

6. Publish to GitHub Pages

  1. Create a GitHub repository named job-tracker. GitHub Free requires a public repository for Pages. GitHub Pro supports Pages from private repositories. The website itself is ordinarily public; your app data still requires Supabase sign-in. GitHub Pages availability.
  2. Upload the extracted contents of the app ZIP to the repository root using Add file → Upload files. Upload individual app files, not the ZIP. index.html must be at the root, not inside an extra folder.
  3. Commit the files to main.
  4. Open Settings → Pages. Under Build and deployment, choose Deploy from a branch, select main and / (root), then Save.
  5. Wait for GitHub's deployment. Open the site URL shown on that page, usually https://YOUR-USERNAME.github.io/job-tracker/.
  6. If shown, enable Enforce HTTPS. Relative asset paths support repository subdirectories.

GitHub publishing-source instructions. No GitHub Actions configuration, npm installation or build step is needed.

7. Load your supplied research once

  1. Open your deployed tracker and sign in with the user you created in Supabase Authentication.
  2. The tracker will initially be empty. Click Backup, type IMPORT, and select the separate initial-tracker.json file downloaded with this delivery.
  3. Confirm the import. Wait for the status to show Synced. The sidebar shows it on larger screens; errors also appear in a banner on phones.
  4. Confirm that you see 28 opportunities and 27 prep tasks.
  5. In Supabase Table Editor, tracker_state should now contain one row. Your jobs, tasks and reference research are stored in its payload column. You normally edit everything in the app, not this table.

Research comes only from your supplied document. Unknown posting dates stay unknown. Salary fields include role ranges, labeled company ranges and unconfirmed figures so you can organize all available pay information. Salary sorting uses each range's upper end, with unknown pay last.

8. Confirm cross-device saving

  1. On your computer, check one prep item and wait for a successful cloud save.
  2. On your phone, open the same GitHub Pages URL and sign in using the same account. Do not import the starter file again.
  3. Check that the prep item is already checked. Add a note on the phone and verify it on the computer.

The app checks for cloud changes when you return to it and every 15 seconds while open. It does not provide live co-editing. If two devices edit the same saved version, the second save shows a conflict instead of silently replacing the first. Use Export local edits to keep those changes, then Load cloud copy and reapply what you need. Retry handles temporary network failures. Wait for sync before closing the app.

9. Add it to your home screen

  • iPhone/iPad: open in Safari, tap Share, then Add to Home Screen.
  • Android: open in Chrome and use Install app or Add to Home screen from the menu.
  • Computer: use your browser's install-app option if available, or bookmark the URL.

The app has a manifest, icons and an offline shell. Cloud login and loading need a connection. If a connection drops during an edit, the app keeps a recovery draft on that device and displays a save error; it does not claim offline changes have synced. On reopening online, sign in and use Retry save. Exports are a separate backup, not required for normal syncing.

10. Everyday use and troubleshooting

  • Edit: click a role title. Change salary, notes, URL, status, location or posting date.
  • Organize: drag cards in Custom order, or use ↑/↓. Filter by region, status or role/watchlist. Sort by location, salary upper end or posting date.
  • Add a listing: save a URL, paste the listing text, extract a draft, review it, then Save. URL-only automatic scraping is not included.
  • Back up: Backup → EXPORT downloads all tracker data and reference context. Keep the file private. IMPORT replaces the current tracker after confirmation.
  • Setup screen persists: check config.js for your actual Supabase URL and public key. Save/commit, wait for Pages to redeploy, then reload.
  • Invalid login: verify the Supabase Auth user exists and is confirmed, and Email sign-in is enabled. Your database password is not your app password.
  • Table not found / permission error: rerun the provided SQL in the correct project, confirm the Data API is enabled for the public schema, and check the key belongs to that project.
  • Cloud connection fails: check connectivity and whether Supabase has paused the project; resume it through the dashboard if needed.
  • Forgot password: manage the account in Supabase Authentication. No email-recovery UI is included in this first version.
  • Need to update: edit the app files, commit them to GitHub, wait for Pages to deploy, and reload. Keep config.js values. The database persists separately.
  • Signed out phone: sign in again. Saved jobs remain in Supabase. Each device has its own session.
