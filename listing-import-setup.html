NEXT CHAPTER / TRACKER UPDATE

Add a job by URL.

The tracker can now fetch a public listing, extract its fields, and let you review them before saving. The list shows a short summary; the full description stays inside the opportunity editor.

This update is built and tested locally, but is not deployed to your accounts. Complete both parts below: add one Supabase Edge Function, then upload the frontend update to GitHub. Your existing database and saved tracker data stay in place. No new database SQL, AI API key or additional scraping service is required.

Part 1 — Deploy the Supabase function

  1. Open your Supabase project's Edge Functions page. If the direct link redirects, select your TrackerApp project and choose Edge Functions in the sidebar.
  2. Choose Deploy a new function → Via Editor. Use the Hello World template or start from scratch.
  3. Name the function fetch-listing. The exact name matters.
  4. In the downloaded ZIP, open supabase/fetch-listing/index.ts in Notepad or another plain-text editor.
  5. Select and copy its entire contents. Replace all of the default code in the dashboard's index.ts editor with it. No other source files or dependencies are needed.
  6. Keep the function's Verify JWT authentication setting enabled. The tracker supplies the signed-in user's token; the function also verifies it with Supabase Auth.
  7. Click Deploy function and wait for success. Its endpoint should end in /functions/v1/fetch-listing.

The function reads Supabase's automatically provided project URL and client keys. It forwards your sign-in token only to Supabase Auth, never to the job website. By default it accepts your existing Pages origin, https://millersgit.github.io. The Pages repository path is not part of the origin. Official dashboard deployment guide · Function authentication.

Part 2 — Update the GitHub Pages files

  1. Open your TrackerApp repository.
  2. Choose Add file → Upload files.
  3. From the ZIP's github-pages folder, upload the files inside that folder to the repository root: app.js, cloud.js, style.css, sw.js, and listing-import-setup.html. Replace the existing files with those names. Do not upload the enclosing folder as a new subdirectory.
  4. Commit the changes to main. Wait for Pages to finish deploying.
  5. Open your tracker and reload with Ctrl+Shift+R. On your phone, reload the app after deployment too.
  6. Sign in normally. You do not need to import the starter file again or rerun the database SQL.

Use the new importer

  1. Click Add opportunity, or click an existing role title to edit it.
  2. Paste the URL for one specific job into Job listing URL.
  3. Click Fetch listing. Wait for the review panel.
  4. The panel shows the company, role, location, salary, posting date, short summary and full description when the source provides them. Empty fields are selected automatically. Replacements for existing values are unchecked by default: select the ones you want to update.
  5. Click Apply selected details. Review the actual editor fields, including Date posted.
  6. Click Save opportunity and wait for Synced.

Fetching and applying do not save the opportunity by themselves. Status, location priority and personal fit notes are kept. The job summary is an editable excerpt of the listing, not an AI fit assessment. Unknown dates and salaries remain unknown; they do not erase existing values.

The importer handles the iCIMS content frame automatically and reads the listing's structured job data. The full job description is kept in its own field, separate from the compact card summary.

Tidy existing oversized entries

Cards are now limited to a short excerpt, including cards whose notes already contain a pasted website. Open one of those entries. If its notes are long and the description is empty, choose Move long pasted notes into full description. Review the summary, notes and description, then save. Your original text is preserved in the full description field. You can also fetch that job's individual URL to obtain its posting date and other fields.

The optional manual-text extractor also now fills the full description instead of dumping text into fit notes. It recognizes exact ISO dates, U.S. month/day/year dates, and written month dates near a “posted” label. A relative date such as “3 months ago” alone does not create an invented calendar date.

If something goes wrong

  • No Fetch listing button: the new app.js has not loaded yet. Check that it is at the repository root, wait for deployment, then hard refresh.
  • “Importer is not deployed”: deploy the function in the same Supabase project used by config.js, with the exact name fetch-listing.
  • “Sign in” / session expired: leave preview mode, sign out and sign back in. Dashboard tests with only an anon/public key are expected to fail because fetching requires a real signed-in user.
  • 401 before the function runs: confirm you are signed in to this project, and inspect the function's Logs/Invocations. Keep JWT verification enabled; do not make the endpoint public to work around an authentication error.
  • Website not allowed: the function accepts https://millersgit.github.io by default. For a future custom domain, set the Supabase Edge Functions secret LISTING_ALLOWED_ORIGIN to the new origin, or a comma-separated list of allowed origins, then redeploy the function.
  • Missing Supabase environment configuration: this function needs the hosted project's built-in SUPABASE_URL and either its built-in publishable-keys dictionary or legacy SUPABASE_ANON_KEY. Do not substitute a service-role key.
  • Site blocked, timed out or unreadable: some sites require sign-in, run all job details in JavaScript, or block server requests. Try the employer's direct listing. This importer does not bypass login screens, CAPTCHAs or access restrictions. Manual entry remains available as a fallback.
  • Fields found but date missing on the card: select the Date posted checkbox, click Apply selected details, confirm the date in the editor, then Save opportunity. If the source lacks an exact date, it remains unknown.
  • Refetch did not change an existing salary or title: replacements are unchecked by default. Select those fields in the review panel before applying.
